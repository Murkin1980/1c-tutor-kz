# FOUNDATION — неизменяемые принципы проекта 1C Tutor KZ

## 1. Продуктовая цель

Обучить владельца ИП практически выполнять основные бухгалтерские операции в «1С:Бухгалтерия для Казахстана», а не просто смотреть видео или читать теорию.

## 2. Неизменяемые правила

1. Основной язык интерфейса MVP — русский.
2. Архитектура должна допускать добавление казахского языка.
3. Денежный формат — KZT, локаль `ru-KZ`.
4. Учебные суммы и примеры указываются в тенге.
5. Тренажёр не выдаёт себя за официальный продукт фирмы «1С».
6. Тренажёр не копирует и не распространяет закрытые материалы, конфигурации и базы 1С.
7. Реальная 1С открывается отдельно, а тренажёр управляет обучением.
8. Пользователь работает только в отдельной учебной базе, не в боевой бухгалтерии.
9. В MVP нельзя требовать ЭЦП, реальные банковские ключи, реальные пароли или реальные данные клиентов.
10. Любая AI-проверка должна быть вспомогательной. Пользователь всегда может пройти урок без AI.
11. Каждый урок должен приводить к наблюдаемому результату.
12. Прогресс должен сохраняться между устройствами.
13. Никакой преждевременной сложной автоматизации до завершения базового MVP.

## 3. Методика обучения

Каждый урок строится по циклу:

1. **Контекст:** зачем операция нужна предпринимателю.
2. **Цель:** какой результат должен появиться в 1С.
3. **Подготовка:** какие исходные данные использовать.
4. **Действие:** один короткий маршрут по интерфейсу.
5. **Проверка:** вопрос, число, выбранный вариант или снимок экрана.
6. **Обратная связь:** объяснение ошибки без наказания.
7. **Закрепление:** похожая задача с другими данными.

## 4. Границы первой версии

В первую версию не входят:

- автоматическое управление интерфейсом 1С;
- хранение реальных бухгалтерских баз;
- отправка реальной налоговой отчётности;
- интеграция с банками;
- работа с ЭЦП;
- автоматическое проведение документов в 1С;
- браузерное расширение;
- полноценный LMS для сторонних школ;
- маркетплейс курсов;
- мобильное приложение.

## 5. Правило для кодера

Перед началом каждой задачи кодер обязан:

1. прочитать `FOUNDATION.md`;
2. указать применимые разделы;
3. проверить, не расширяет ли задача границы MVP;
4. описать изменения до написания кода;
5. после реализации обновить документацию и тесты.
