## Текущая контрольная точка

Опубликовать frontend в Cloudflare Pages и подтвердить:

- прямое обновление SPA-маршрутов;
- применение `_headers`;
- основной e2e-сценарий на preview URL;
- отсутствие секретов в клиентском bundle.

До выполнения этой точки этап 1 считается локально завершённым, но не принятым как опубликованный preview.

## Подтверждено

- `main` синхронизирован с публичным репозиторием GitHub;
- React-прототип содержит семь требуемых маршрутов;
- mock-курс содержит 2 модуля и 5 уроков;
- локальный прогресс восстанавливает незавершённый урок;
- реализованы семь типов проверки MVP;
- unit/integration-тесты, build и desktop/mobile e2e прошли в итерации 1;
- bundle проверен на маркеры server-side секретов.

## Известные ограничения

- mock-авторизация и прогресс работают только в текущем браузере;
- клиентская роль не является серверной защитой `/admin`;
- `screenshot_manual` ещё не загружает файлы в приватный Storage;
- контент требует методической проверки на утверждённой версии 1С;
- GitHub Actions не используется из-за исчерпанного лимита владельца;
- Cloudflare Pages preview пока отсутствует.

## Следующий рекомендуемый этап

После публикации preview выполнить одну отдельную итерацию Supabase: Auth, начальные миграции, RLS и серверный repository для прогресса и заметок. CRUD, Storage и AI в неё не включать.
