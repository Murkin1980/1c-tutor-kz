# PRODUCT REQUIREMENTS — 1C Tutor KZ

Обновлено: 2026-08-15.

## 1. Проблема

Начинающему пользователю недостаточно видео, текста или теста. Чтобы научиться 1С, он должен привыкнуть к структуре интерфейса, самостоятельно выполнять хозяйственные операции, видеть последствия своих действий и получать проверку реального результата.

Первый прототип не решал эту задачу: он зависел от платного внешнего 1C:Fresh и мог засчитать практический урок по введённому ответу без выполнения операции.

## 2. Решение

Веб-приложение с встроенной **Training Workspace** — ограниченной интерактивной учебной репликой поддерживаемых процессов 1С:Бухгалтерии для Казахстана.

Training Workspace соединена с системой обучения и поэтому знает:
- где находится пользователь;
- какие действия он выполнил;
- какие учебные объекты созданы;
- какие поля и суммы сохранены;
- достигнут ли требуемый бизнес-результат;
- сколько подсказок использовано.

## 3. Jobs To Be Done

- Когда я впервые изучаю 1С, я хочу безопасно нажимать те же типы кнопок и заполнять похожие формы, чтобы потом не потеряться в реальной программе.
- Когда я выполняю задачу, я хочу видеть, что именно система проверяет, чтобы понимать свою ошибку.
- Когда я застрял, я хочу получить подсказку в нужном месте интерфейса, а не искать её в длинной инструкции.
- Когда я готов проверить себя, я хочу выполнить хозяйственную задачу без пошаговой помощи.
- Когда я обучаю сотрудника, я хочу отличать самостоятельное выполнение от выполнения с подсказками.

## 4. Целевые пользователи MVP

### Владелец ИП
Не бухгалтер. Осваивает базовый документооборот и контроль расчётов.

### Новый сотрудник
Должен научиться безопасно выполнять типовые операции до допуска к рабочей базе.

## 5. Core experience

### 5.1 Training Workspace
Обязательны:
- 1C-like shell;
- разделы/списки/формы только для поддерживаемых сценариев;
- вымышленные seed-данные;
- создание/изменение учебных объектов;
- детерминированный reset;
- видимая маркировка учебной среды;
- desktop и mobile usability.

### 5.2 Три режима

#### Показать
Автоматическая демонстрация с объяснениями. Не оценивается.

#### Вести меня
Пользователь действует сам. Coach показывает текущий релевантный контрол и переходит дальше только после валидного действия/состояния.

#### Проверить себя
Только бизнес-задача и исходные данные. Нет пошаговых bubbles. Результат определяется state verification.

### 5.3 Context coach
- anchored bubble;
- spotlight;
- step progress;
- `Почему?`;
- двухуровневые hints;
- `Показать действие` в guided/demo;
- не перекрывать целевой контрол;
- уметь продолжить после допустимого свободного действия пользователя.

### 5.4 Проверка работы
Практический сценарий содержит набор state assertions. Пользователь видит понятный список PASS/FAIL.

Запрещено засчитывать практическое задание только по quiz/self-confirm/text/number answer.

### 5.5 Progress semantics
Для каждого сценария сохраняются:
- mode;
- started/completed;
- passed assertions;
- hint count;
- show-action count;
- retries/resets;
- `completed_unassisted` / `completed_assisted` / `not_completed`.

## 6. Первый вертикальный срез

`Карточка учебного покупателя`.

Пользователь должен:
1. открыть Training Workspace;
2. найти раздел/справочник контрагентов;
3. нажать создание;
4. заполнить вымышленные поля;
5. сохранить;
6. получить state-based verification;
7. исправить ошибку без потери сценария;
8. сбросить сценарий;
9. пройти его в Independent Test.

### Acceptance
- операция выполняется без внешнего 1C:Fresh;
- правильный текст, введённый вне Workspace, не может дать PASS;
- verification показывает минимум: объект создан / имя / обязательные учебные поля / сохранён;
- Guided режим действительно ждёт действия;
- Test режим скрывает пошаговые указания;
- owner UX review = PASS до расширения scope.

## 7. Второй и третий срезы после PASS

2. Счёт покупателю: контрагент, строки, количество, цена, сумма, статус.
3. Оплата/аванс: платёж, связь с покупателем/документом, изменение учебного расчётного состояния.

## 8. UX-принципы

- workspace первичен, учебный текст вторичен;
- обучение происходит действием;
- помощь находится в контексте;
- ошибка является диагностикой, а не просто `Неверно`;
- постепенно убирать поддержку;
- у пользователя всегда есть reset/retry;
- бизнес-смысл объясняется кратко возле действия или после результата;
- никакого обязательного переключения между двумя вкладками в MVP.

## 9. Метрики пилота

- completion первого практического сценария;
- unassisted completion rate;
- среднее число hints/show-action;
- state assertions, на которых чаще всего ошибаются;
- время до первого успешного результата;
- повторное прохождение без помощи;
- субъективная уверенность до/после;
- transfer test в реальной/демо 1С — только на более позднем этапе.

## 10. Нефункциональные требования

- TypeScript strict;
- deterministic state and tests;
- основной сценарий доступен с клавиатуры;
- coach не блокирует control на desktop/mobile;
- responsive до 360px;
- отсутствие секретов/реальных бухгалтерских данных;
- Cloudflare-compatible static deployment для Stage 1B;
- состояние MVP локальное через repository abstraction; server persistence добавляется только после доказанной ценности.

## 11. Вне Stage 1B

- полный клон 1С;
- платный 1C:Fresh как обязательная зависимость;
- реальные ИИН/БИН/пароли/ЭЦП;
- синхронизация с рабочей 1С;
- FNO/ESF;
- AI как verifier;
- computer vision;
- browser extension;
- Supabase до отдельного MPE решения;
- платежи, сертификаты, SCORM и корпоративная LMS.
