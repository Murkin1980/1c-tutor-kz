# 1C Knowledge Atlas

## Назначение

`knowledge/1c/` — постоянный структурированный источник знаний проекта 1C Tutor KZ.

Кодер и будущие агенты должны сначала искать здесь сведения о конфигурациях, версиях, интерфейсах, командах, объектах и бизнес-процессах. Интернет используется для пополнения или проверки Atlas, а не как основной источник при каждой реализации.

## Почему Atlas

Экосистема 1С состоит из платформы и множества конфигураций. Один и тот же базовый объектный язык (справочники, документы, отчёты, формы, команды) повторяется в разных решениях, но конкретные процессы, названия, экраны и правила зависят от конфигурации и версии.

Atlas разделяет общую платформенную модель и конфигурационно-специфические знания.

6. Общие пользовательские механизмы платформы `1С:Предприятие 8`.

Не пытаться заполнить все конфигурации сразу. Atlas расширяется по demand-driven правилу: сначала данные, необходимые ближайшему vertical slice, затем систематическое покрытие при переходе к Stage K1.

## Источники

Приоритет:
1. официальная документация `its.1c.kz` / `1c.kz`;
2. официальная документация платформы и releases `its.1c.ru`, `v8.1c.ru`, `downloads.v8.1c.ru`;
3. официальные учебные материалы 1С, если доступны законно;
4. проверенные партнёрские/методические материалы как secondary evidence;
5. видео/форумы/блоги только как вспомогательные сигналы, требующие подтверждения.

## Copyright / provenance

Atlas НЕ является зеркалом ИТС и не копирует массово чужие тексты, скриншоты, книги или закрытые материалы.

Мы сохраняем:
- URL и метаданные источника;
- дату наблюдения;
- конфигурацию/версию;
- собственное краткое структурированное описание факта;
- при необходимости короткий допустимый фрагмент;
- confidence и статус проверки.

## Правило для реализации

Перед созданием нового 1C-like экрана или workflow:
1. запросить Atlas;
2. найти Configuration + Version + BusinessArea + Workflow;
3. проверить Interface Passport;
4. проверить source freshness/confidence;
5. если данных недостаточно — создать ingestion task, исследовать источники и добавить evidence;
6. только затем писать UI/domain logic.

Если Atlas и интернет расходятся, новая информация не заменяет старую молча: создаётся новая version/evidence запись.
