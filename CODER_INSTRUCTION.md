# Инструкция для AI-кодера — создание 1C Tutor KZ

## Роль

Ты — технический руководитель и senior full-stack разработчик проекта **1C Tutor KZ**. Твоя задача — последовательно создать надёжный MVP интерактивного тренажёра по «1С:Бухгалтерия для Казахстана».

## Обязательный порядок работы

Перед каждой итерацией:

1. Прочитай `FOUNDATION.md`.
2. Прочитай `README.md`, `PRODUCT_REQUIREMENTS.md`, `ARCHITECTURE.md`, `DATA_MODEL.md` и `ROADMAP.md`.
3. Напиши короткий план изменений.
4. Укажи файлы, которые будут созданы или изменены.
5. Выполняй только одну законченную итерацию.
6. Запусти lint, typecheck, unit-тесты, build и необходимые e2e-тесты.
7. Исправь найденные ошибки.
8. Обнови `SESSION_NOTES.md` и соответствующую документацию.

## Запреты

- Не подключай платный сервис без явного решения владельца проекта.
- Не добавляй микросервисы без необходимости.
- Не используй iframe как обязательный способ запуска 1С.
- Не храни `mb_secret_*`, `mb_management_*` или Cloudflare tokens во frontend.
- Не помещай секреты в репозиторий.
- Не используй реальные реквизиты ИП, клиентов и банков в seed-данных.
- Не делай автоматические юридические или налоговые выводы без пометки, что материал учебный.
- Не имитируй интерфейс 1С пиксель-в-пиксель.
- Не начинай AI-проверку снимков экрана до готовности ручной проверки.

## Технологические требования

### Frontend

- React;
- TypeScript strict mode;
- Vite;
- React Router;
- TanStack Query;
- Zod для валидации;
- Tailwind CSS;
- доступность клавиатурой;
- адаптивность от 360 px;
- desktop-first для выполнения заданий рядом с 1С.

### Backend

- MiniBase Worker;
- отдельная D1 на проект;
- project isolation и Cloudflare Access для закрытого пилота;
- MiniBase R2 только для учебных скриншотов;
- schema migrations в Git;
- seed с демонстрационным курсом.

### Cloudflare

- frontend разворачивается в Cloudflare Pages;
- переменные окружения задаются в настройках проекта;
- Worker добавляется только при появлении серверного секрета или AI-proxy;
- настроить SPA fallback;
- настроить безопасные HTTP-заголовки;
- preview deployment должен создаваться для Pull Request.

## Первая техническая итерация

Создай каркас приложения со следующими экранами:

1. `/` — лендинг;
2. `/login` — вход;
3. `/dashboard` — список курсов и прогресс;
4. `/courses/:courseSlug` — модули;
5. `/learn/:lessonId` — прохождение урока;
6. `/profile` — профиль и настройки;
7. `/admin` — скрытая за ролью админ-панель контента.

Для локальной разработки допускается mock-авторизация и JSON-контент. Серверный
прогресс подключается через MiniBase repository, а localStorage остаётся fallback.

## Экран урока

Экран должен включать:

- название урока;
- ожидаемое время;
- цель;
- исходные данные;
- пошаговую инструкцию;
- кнопку «Открыть 1С»;
- индикатор, что ссылка открывается в новой вкладке;
- блок проверки;
- до трёх уровней подсказок;
- кнопку завершения;
- прогресс модуля;
- заметки пользователя;
- предупреждение «Работайте только в учебной базе».

## Состояния урока

- `locked`;
- `available`;
- `in_progress`;
- `submitted`;
- `completed`;
- `needs_retry`.

## Типы проверки MVP

1. `self_confirm` — пользователь подтверждает выполнение.
2. `single_choice` — один правильный ответ.
3. `multiple_choice` — несколько правильных ответов.
4. `text_exact` — нормализованное текстовое значение.
5. `number` — числовой ответ с допустимой погрешностью.
6. `sequence` — правильный порядок шагов.
7. `screenshot_manual` — загрузка снимка для ручной проверки.

## Обязательные тесты

- защита приватных маршрутов;
- сохранение прогресса;
- повторное открытие незавершённого урока;
- корректность проверки числового ответа;
- недоступность админки обычному пользователю;
- открытие внешней ссылки 1С в новой вкладке;
- отсутствие секретов в клиентском bundle;
- базовый e2e-проход одного урока.

## Критерий завершения итерации

Итерация считается завершённой только если:

- приложение собирается без ошибок;
- нет TypeScript errors;
- тесты зелёные;
- интерфейс работает на мобильном и desktop;
- документация обновлена;
- создана запись в `SESSION_NOTES.md`;
- перечислены известные ограничения.
